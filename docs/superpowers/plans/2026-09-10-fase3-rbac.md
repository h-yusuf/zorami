# Fase 3 — RBAC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aktifkan multi-user dengan tiga peran (Owner, Operator, Viewer). Tambah tabel `roles`, `memberships`, `invitations`. Undangan via email/kode. Penegakan izin di setiap endpoint REST dan WebSocket. Pisah izin "baca transkrip" dari "putar rekaman audio". Setelah fase ini, sistem berjalan dari satu pemilik tunggal ke multi-user terisolasi penuh.

**Architecture:** Tidak ada paket baru. Fase 3 memperluas `control/` (REST endpoints untuk users/roles/invitations) dan `core/` (model data + penegakan izin). `device/` tidak diubah — penegakan izin terjadi di lapisan `control/` sebelum mencapai device/event bus.

**Tech Stack:** Tidak ada dependency baru. Pakai yang sudah ada: FastAPI, SQLAlchemy 2.0 (async), Pydantic v2, argon2id, JWT. Alembic untuk migrasi skema.

**Spec:** [docs/superpowers/specs/2026-09-10-zora-bridge-system-design.md](../specs/2026-09-10-zora-bridge-system-design.md) §9 poin 14. [docs/superpowers/specs/2026-09-10-zora-bridge-ui-design.md](../specs/2026-09-10-zora-bridge-ui-design.md) §4.7.

## Global Constraints

- **Jangan tulis kode/config library manual.** Pakai command resmi (`alembic revision`, `npx tsc --init`, dll). File config di-generate oleh command resmi, lalu di-patch.
- `owners` table sudah dipisah dari `users` sejak Fase 1 — "biar RBAC nanti gampang." Fase 3 cukup tambah `roles`, `memberships`, `invitations` tanpa merusak data yang ada.
- Izin "baca transkrip" DIPISAH dari "putar rekaman audio". Operator mendapat yang pertama tanpa yang kedua (spec §4.7).
- Tidak boleh ada downgrading peran diri sendiri tanpa konfirmasi — Owner terakhir tidak boleh turun jadi Operator/Viewer (spec §4.7 edge case).
- Undangan kedaluwarsa — default 7 hari (spec §4.7 edge case).
- Pendaftaran terbuka default MATI. Hanya lewat undangan (spec §4.7).
- Semua endpoint REST + WebSocket wajib pakai permission check, bukan hanya auth check. `Depends(get_current_owner)` → ganti dengan `Depends(require_permission("agents:write"))`.
- Timestamp semua UTC.

### Model: `memberships`

```python
class Membership(Base):
    __tablename__ = "memberships"
    id: Mapped[str] = mapped_column(String, primary_key=True, default=uuid4str)
    owner_id: Mapped[str] = mapped_column(ForeignKey("owners.id"), nullable=False)
    user_id: Mapped[str] = mapped_column(ForeignKey("users.id"), nullable=False)
    role_id: Mapped[str] = mapped_column(ForeignKey("roles.id"), nullable=False)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    # Unique constraint: (owner_id, user_id) — satu user cuma bisa satu peran per owner
    __table_args__ = (UniqueConstraint("owner_id", "user_id", name="uq_membership_owner_user"),)
```

Catatan: `owner_id` di sini merujuk ke `owners.id` — yaitu tenant/akun pemilik. User yang membuat tenant = Owner. User lain yang diundang = Operator atau Viewer.

### `app/core/permissions.py`

```python
# Permission codenames
AGENTS_WRITE = "agents:write"
AGENTS_READ = "agents:read"
PROVIDERS_WRITE = "providers:write"
PROVIDERS_READ = "providers:read"
DEVICES_WRITE = "devices:write"
DEVICES_READ = "devices:read"
MONITOR_READ = "monitor:read"
CONVERSATIONS_READ = "conversations:read"
CONVERSATIONS_AUDIO = "conversations:audio"
CONVERSATIONS_DELETE = "conversations:delete"
USERS_MANAGE = "users:manage"

# Matriks peran → permissions
ROLE_PERMISSIONS: dict[str, set[str]] = {
    "owner": {
        AGENTS_WRITE, AGENTS_READ, PROVIDERS_WRITE, PROVIDERS_READ,
        DEVICES_WRITE, DEVICES_READ, MONITOR_READ,
        CONVERSATIONS_READ, CONVERSATIONS_AUDIO, CONVERSATIONS_DELETE,
        USERS_MANAGE,
    },
    "operator": {
        AGENTS_WRITE, AGENTS_READ,
        DEVICES_WRITE, DEVICES_READ, MONITOR_READ,
        CONVERSATIONS_READ, CONVERSATIONS_DELETE,
    },
    "viewer": {
        AGENTS_READ, DEVICES_READ, MONITOR_READ,
        CONVERSATIONS_READ,
    },
}

def has_permission(role_id: str, permission: str) -> bool:
    """Check if role has permission."""
    perms = ROLE_PERMISSIONS.get(role_id, set())
    return permission in perms

def get_role_permissions(role_id: str) -> set[str]:
    """Return all permissions for a role."""
    return ROLE_PERMISSIONS.get(role_id, set()).copy()
```

### Modify: `app/control/auth.py`

Ganti `get_current_owner` dengan `get_current_user_with_role` yang return `(user_id, owner_id, role_id)`:

```python
async def get_current_user_with_role(
    credentials: HTTPAuthorizationCredentials = Depends(bearer),
    db: AsyncSession = Depends(get_session),
) -> tuple[str, str, str]:
    """Returns (user_id, owner_id, role_id). Gunakan di endpoint REST."""
    user_id = decode_access_token(credentials.credentials)
    if user_id is None:
        raise HTTPException(status_code=401, detail="Token tidak valid")

    result = await db.execute(
        text("""SELECT m.owner_id, m.role_id FROM memberships m
                WHERE m.user_id = :uid"""),
        {"uid": user_id}
    )
    row = result.fetchone()
    if row is None:
        raise HTTPException(status_code=403, detail="User belum punya membership")

    return user_id, str(row.owner_id), str(row.role_id)
```

Dan factory dependency `require_permission`:

```python
from app.core.permissions import has_permission

def require_permission(permission: str):
    """Factory: returns FastAPI dependency that checks permission."""
    async def checker(
        ctx: tuple[str, str, str] = Depends(get_current_user_with_role),
    ) -> tuple[str, str, str]:
        user_id, owner_id, role_id = ctx
        if not has_permission(role_id, permission):
            raise HTTPException(status_code=403, detail=f"Akses ditolak: butuh izin '{permission}'")
        return ctx
    return checker
```

### Undangan flow:

1. Owner POST `/api/users/invite` dengan `{email, role_id}`.
2. Bridge generate `code` (32 char random, URL-safe).
3. Bridge kirim email dengan link `/invite?code=XXX` (atau tampilkan kode di UI kalau belum ada SMTP).
4. User baru POST `/api/users/accept` dengan `{code, name, password}`.
5. Bridge cek: kode ada? status=pending? belum kedaluwarsa? → create User (argon2id hash) + create Membership (owner_id dari invitation, role_id dari invitation, user_id baru).
6. Invitation status → `accepted`.

### Edge cases (dari spec §4.7):

- **Undangan kedaluwarsa:** `expires_at < now()` → 410 Gone, "Undangan kedaluwarsa. Minta pemilik untuk mengirim ulang."
- **Downgrading peran diri sendiri:** Owner tidak bisa mengubah peran diri sendiri ke operator/viewer kalau dia satu-satunya Owner di tenant. Cek: `SELECT COUNT(*) FROM memberships WHERE owner_id = ? AND role_id = 'owner'` — kalau 1, tolak dengan 400 "Anda adalah satu-satunya Owner. Tidak bisa menurunkan peran sendiri."

## Pitfalls

1. **Lupa migrate endpoint tertentu:** WebSocket monitor punya auth sendiri (query param). Jangan lupa ganti ke permission check. Cari semua `get_current_owner` di codebase setelah migrasi.
2. **Sole-owner race condition:** Cek `COUNT(*) FROM memberships WHERE role_id='owner'` di transaction yang sama dengan UPDATE/DELETE. Kalau tidak, bisa ada race: dua owner downgrade bersamaan → nol owner.
3. **Undangan code reuse:** Setelah accept, set status='accepted'. Code yang sudah accepted tidak bisa dipakai lagi. Test `test_accept_valid_invitation` lalu coba accept lagi → harus 400/410.
4. **Permission check terlalu longgar:** `require_permission("agents:read")` di endpoint POST (write) — salah mapping. Double-check mapping di Task 28.
5. **Audio endpoint lupa dipisah:** `GET /api/conversations/{id}` (transkrip) dan `GET /api/conversations/{id}/audio/{msg_id}` (audio) punya permission berbeda. Jangan pakai permission yang sama.
6. **Frontend tidak handle 403:** Operator buka halaman Providers → 403 dari API. Frontend harus tangkap 403 → tampilkan pesan "Anda tidak punya izin untuk halaman ini" bukan error generik.
7. **Token lama tidak punya role:** User yang login sebelum Fase 3 punya token tanpa role info. Decode token → cari membership → kalau tidak ada, 403 "Token kedaluwarsa, silakan login ulang." Force re-login.
8. **Undangan code di URL:** Code undangan muncul di URL `/invite?code=XXX`. Pastikan code tidak log di access log (FastAPI default tidak log query param, tapi cek konfigurasi).
9. **Pendaftaran terbuka tanpa guard:** Kalau pendaftaran terbuka diaktifkan, tetap butuh validasi: email unik, password kuat, rate limit. Jangan expose endpoint tanpa guard.
10. **Migrasi data tanpa idempotency:** Migrasi seed membership harus idempotent — kalau dijalankan ulang, tidak duplikat. Pakai `WHERE NOT EXISTS`.
